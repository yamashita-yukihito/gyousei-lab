## 2. やってほしいこと

### 2.1 民法演習Dで見つかった候補を確かめる（いちばん収穫が見込める）

2026-10-20〜21に、民法演習D（`static/minpo-d/chapters.json`）を23章184問へ広げた。
全問を、20年分の過去問で実際に問われた論点だけで作り、各問の `examRefs` に年度・問・肢を書いてある。
**184問のうち99問は、学習カードと結んでいない（`cardId` が無い）。** ここにカードの穴が残っている可能性が高い。

次の手順で確かめる。

1. `cardId` の無い問を一覧にする（`examRefs` と `legalBasis` を一緒に出す）。
2. それぞれについて、既存のカード（`content/explanation_cards.json`）に同じ論点が本当に無いかを確かめる。
   `subtopic` だけでなく `legalBasis` の条文番号と A の文で探す。**論点が同じカードがあれば、D案の問に `cardId` を足すだけでよい**（新しいカードは作らない）。
   - `cardId` は論点が一致するときだけ結ぶ（`AGENTS.md` §5.2）。
3. カードが無ければ、20年分の過去問（非公開編集データの `all_subjects/`）で、その論点が**問題単位で2回以上**出ているかを数え直す。
   `examRefs` はD案を作ったときに見つけた分だけで、全部ではない。
   - 数え方と線引きは `AGENTS.md` §5.3。1回だけ・試験範囲外・法改正で出なくなったものは作らない。
   - 法改正で答えが変わった過去問は、今の法律でも結論が同じものだけを数える。
4. 2回以上の論点だけを、§3の手順でカードにする候補として一覧にする（論点・出題箇所・条文・作るなら ○ か × か・A にそのまま使える肢があるか）。

## 3. カードを作るときの手順（作ると決まった分だけ）

書き方の決まりは `AGENTS.md` §5・§5.3、`HANDOFF.md`「問題追加の正本ルール」、`authoring/CARD_AUTHORING.md` が正本。特に次を外さない。

- **A は過去問の肢の原文をそのまま使う**（装飾記法を外した文字列が⑤の肢と1文字も違わない）。例外は `AGENTS.md` §5 の(1)〜(4)のときだけ。`tests/test_variant_a_matches_source.py` が見ている。
- **B・C は A と同じ結論の文**にし、断定型で書く。「この文は」「〜という内容です」のような引用の型を使わない（同じテストが見ている）。B は2案。
- 正解は回答後の `correction`・`explanations`・`memoryPoint` に書く。
- 条文は e-Gov の法令基準日 **2026-04-01** で確かめる。判例は事件名と裁判年月日を確かめる。
- `learningType`（memorize / understand）を必ず付ける。迷ったら understand。
- 同じ科目の ○ と × の釣り合いを崩さない（`authoring/CARD_AUTHORING.md` 1.15）。

正本へ入れる段取り：

1. `content/explanation_cards.json` の `items` に足す。**同じファイルの `studyDecks[0].cardIds` にも同じIDを足す**（足さないとbundle生成が止まる）。
2. ⑤の肢は、非公開編集データ `~/.local/share/yuki-services/gyousei-lab/authoring/canonical/related_question_source.json` の `records`（問題）と `choices`（肢）に登録し、カードの `relatedPastQuestions` と `sourceRefs` から指す。
   旧10年の肢は `sourceEra: "archive"` にし、URLを持たせず、現行法の正誤をe-Govで確かめる（`AGENTS.md` §5.3）。
3. 頻出度監査の正本 `~/.local/share/yuki-services/gyousei-lab/authoring/curation/card_frequency_2006_2025.json` の `cards` に、**同じ作業で**1件ずつ足す（問題キーと年度。ラベルは問題数で機械的に決まる）。先に控えを取る。
4. 全カードを `card_edit.validate_card` に通す（`known_ids` に全ID、`is_new=False`）。エラー0件でなければ書かない。
5. `PYTHONDONTWRITEBYTECODE=1 /opt/homebrew/bin/python3.12 -m unittest discover -s tests` を通す。枚数を書いた文書（`README.md`・`ARCHITECTURE.md`・`HANDOFF.md`）は `tests/test_doc_card_counts.py` が見ているので、落ちたら文書側の数字を直す。
6. bundleを作る：`authoring/` で `GYOUSEI_DATA_ROOT=~/.local/share/yuki-services/gyousei-lab/authoring` を付け、`gyousei_pipeline.production_bundle` を `--compare-to`（稼働中bundle）と `--expected-card-count`（新しい総数）などを付けて走らせる。
   出力は `authoring/builds/releases/gyousei-production.json`。
7. 稼働中の `~/.local/share/yuki-services/gyousei-lab/gyousei-production.json` と比べ、**既存カードが1枚も変わっていないこと、増えたのが意図したカードだけであること**を確かめる。
8. 稼働中bundleを日付つきの名前で控えてから、新しいbundleを権限 `0600` でatomicに置き換える（`install -m 0600` で一時名に置いて `mv`）。APIは自動で再読込するので、`server.py` を変えていなければ再起動は要らない。
9. `GET /api/cards` で枚数を、`GET /api/study-queue` でキューに入ることを確かめる。

## 4. ほかに知っておくこと

1. カードは「平成18年度以降に2回以上出た論点」が原則（`AGENTS.md` §5.3）。基礎知識の一般知識（政治・経済・社会）と文章理解は作らない。
2. 商法・会社法は2問（8点）で満足する方針。商法を厚くしない。記述式を厚くしない（`AGENTS.md` §5.4）。
3. 回答履歴はカードIDに付く。既存カードの論点そのものを変えるなら、新しいIDにする。
4. 学習カードとD案を結ぶと、カードの画面に「民法演習D：章名 →」のリンクが自動で出る（`static/app.js` が `minpo-d/chapters.json` を読む）。
5. 例外：行政書士法の令和7年改正の5枚（`gk-gyosei-law-mission-001` など）は、出題0回でも利用者の指示で足した。頻出度は「未出題」。**ほかの法改正は、利用者が参考書・動画で補うと決めたので、カードにしない。**
