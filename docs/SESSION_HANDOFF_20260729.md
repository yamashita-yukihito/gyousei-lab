## 2. このセッションでやったこと

### 2-1. 未出題の論点をカードにしていた（利用者からの指摘）

住民基本台帳法の「氏名の振り仮名」カードを、令和7年改正の号ずれを根拠に
**ひっかけとして出題される**という前提で作っていた。利用者に問われて
1,139問を検索したところ、**この論点の出題は0件**だった。

カードを取り下げ、`authoring/CARD_AUTHORING.md` に **§1.1「出題された論点だけを
カードにする」** を追加した。改正があること自体は、出題実績の代わりにならない。

### 2-2. 全カードへ元問題リンクを追加

利用者のFPサイトと同じく、カードから元の過去問へ飛べるようにした。
`production_bundle.py` の `_attach_source_question_links()` が `sourceRefs` へ
`eraYear` / `questionNumber` / `providerUrl` を足す。公開projectionは維持している。

### 2-3. bundle生成の既定値が行政法だけへ縮む罠を塞いだ

`gyousei-production-bundle` の既定入力が行政法のパスを向いていたため、
何も考えずに再生成すると**他5科目がまるごと落ちた**bundleができる状態だった。
既定を全科目へ変え、さらに `--compare-to`（既定は稼働中bundle）で
過去問・カード・⑤・科目別・形式別の件数が減っていれば**失敗する**ようにした。
意図的に減らすときだけ `--allow-shrink` を付け、完了報告に何を減らしたか書く。

### 2-4. 4科目のカードを新規作成（計51枚）

商法15枚 → 憲法20枚 → 基礎法学10枚 → 基礎知識6枚 → 一般知識7枚。

このとき**憲法20枚が全部×**だった。「迷ったら×」で満点が取れてしまう。
20年集計をやり直して○にできる論点を選び、憲法10枚・商法3枚を○へ書き換えた。
`CARD_AUTHORING.md` に **§1.15「○と×のバランスを必ず確認する」** を追加。

### 2-5. 20年集計と頻出度の正直化

行政法・民法以外は10年集計しかなく、頻出度の根拠が弱かった。20年で集計し直し、
UIに「20年の出題傾向」と固定表示していたのを `frequencySpanLabel(scope)` で
**カードごとの実際の集計範囲**を出すよう直した（10年集計のカードに20年と
書いていたのは事実と違う）。`CARD_AUTHORING.md` §1.17 に記録。

### 2-6. 科目横断の⑦を新設

⑦を三法比較（行手法・行審法・行訴法）だけでなく、**民法と商法**、
**民法と国家賠償法**のように科目をまたぐ比較にも使うことにした。15枚。
`AGENTS.md` §5 の⑦の定義を書き換えてある。

### 2-7. 公開後のレビュー対応

利用者が別AIに `kuruma-matome.com` 経由の公開とBasic認証を実装させ、
監査レポート `GYOUSEI_LAB_REVIEW_2026-07-29.md` を受け取った。指摘は全部正しかった。

**最重要だったのは、公開URLから回答が保存できない不具合。** 原因はnginxの
`proxy_set_header X-Forwarded-Proto $scheme;` で、さくら経由の `https` が
`http` に潰され、server.pyのOrigin照合が403を返していた。
`$http_x_forwarded_proto` へ変えて解消（403→400を確認）。

あわせて、`card_marks` を**押した時点のカード版に対する判断**として扱うよう
revision照合を入れ（`staleMarks` / `staleRevisionMarks`）、
`weakness_analysis.py` をschema 3と4の両方に対応させた。

## 4. 触るときに気をつけること

- **B・CはAと同じ結論の文にする。** A・B1・B2・Cは回答ボタンより上にあり、
  回答前に全部読める。B・CがAの逆や正解を書くと○×が割れる。
  過去に44枚が割れていて利用者に指摘された。断定型で書く
- `!!赤!!` は「判定の分かれ目」。○のカードにも付けてよい。
  「ひっかけ」の意味に戻すと、赤の有無で答えが割れる
- 回答revisionが変わるのは **A・C・correct・lawAsOf** の変更のみ。
  Bや解説や⑥⑦を直しても履歴は生きたまま。この違いを意識して編集する
- bundleを作り直したら、**必ず** `--compare-to` の結果を見る（既定で有効）
- `static/` はnginxが直接配信するので、保存した瞬間に本番へ出る。試作を置かない。
  JS/CSSを変えたら `APP_VERSION` と `index.html` のクエリ版を同時に更新する
  （現在 `20260729-6`）
- nginx正本は `~/dev/yuki-services/deploy/macos/nginx/yuki-services.locations.conf`。
  **gyousei-labリポジトリへコピーしない**（このセッションで一度やってしまい戻した）
- 回答POSTを含むブラウザテストは本番SQLiteへ向けない。別ポート・一時DBで行う
