## 1. コンセプト: 「1場面 × N命題」

### 何が違うか

| 観点 | A案 | B案 |
|---|---|---|
| **構造** | 1場面 → 1問（○×） | **1場面 → 5〜10個の○×命題** |
| **場面の伝え方** | SVG関係図 + テキスト | **生成画像 + テキスト**（画像で直感、文章で正確に） |
| **事例文** | 2〜3文 | **やや長め（3〜5文）**。1場面で多くの命題を解くので、設定を丁寧に書く |
| **解説** | correction + point | **命題ごとのステップ解説**（条文の要件を追う） |
| **テーマ** | 明るい | **明るい**（gyousei-lab本体と統一感を持たせつつ、独自性あり） |

### なぜこの形か

ユーザーの問題意識:「100問解くのに100回場面を読み直すのは非効率」

→ **1つの場面を1回読めば、その場面について5〜10個の論点を連続で解ける**。場面把握は1回で済み、法律知識の習得だけに集中できる。

例: 「しずかがのび太に甲土地を売った。のび太は登記未了。スネ夫がしずかから同じ土地を買い登記した」という1場面で:
- 命題1: のび太は登記なしでスネ夫に対抗できるか（177条の基本）
- 命題2: スネ夫が悪意なら結論は変わるか（悪意者と第三者）
- 命題3: スネ夫が背信的悪意者なら？（背信的悪意者排除法理）
- 命題4: しずかは二重譲渡の責任を負うか（債務不履行）
- 命題5: のび太が先に建物を建てていたら？（対抗問題と占有）

### ポイント

- `statements` の数は場面に応じて自由（5〜10個が目安）
- 各 statement は独立した○×命題。1つずつ順番に出すか、一覧で出すかはUIで決める
- `explanation.steps` で条文の要件を1つずつ追う

└──────────────────────────────────┘
```

### 3.3 フロー

1. 場面表示（画像＋テキスト）は**ページ上部に固定表示**。スクロールしても見える。
2. その場面に属する命題を**1つずつ**表示。
3. ○×を選ぶと即座に正誤判定 → ステップ解説が展開。
4. 「次の命題」で同じ場面の次の命題へ。
5. その場面の全命題が終わったら**場面サマリー**（正解数/全問数 + 間違えた命題のリスト）。
6. 「次の場面」で次のシーンへ。

## 5. 画像

- 1場面につき1枚。回答前に表示。
- generate_image で生成。
- **水彩風のシンプルなイラスト**。キャラクターはドラえもんそのものではなく、配色で区別できる人物アイコン + 名前ラベル。
- 場面の核心（土地の取り合い、契約書を交わす、抵当権の鍵マーク、etc）を描く。
- 横幅 800px、アスペクト比 3:2。
- `static/minpo-b/assets/` に配置。

## 6. 技術仕様

```

├── app.js
├── styles.css
├── problems.json
