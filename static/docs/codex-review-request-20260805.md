## 1. このサービスは何か

1人が自宅LAN内だけで使う、行政書士試験（2026年11月8日受験）の学習サービスです。

- **主役は○×学習カード246枚。** 過去問569問は「本番での聞かれ方の確認」と「カードの根拠を示す」ための参照用で、周回する対象ではありません。
- 静的UI（`static/`）をnginxが直接配信し、`server.py`（Python標準ライブラリだけのHTTPサーバー）が `/api/` を受けます。
- 回答履歴は**追記型のSQLite**が正本です。集計や分析は、そこから毎回導出します。
- カードの本文の正本は Git 管理下の `content/explanation_cards.json` です。過去問の本文・取得元の解説・頻出度監査は**リポジトリの外**（`~/.local/share/...`）にあり、ここには入っていません。

## 2. 今回の変更（何を作ったか）

### A. 「今日の学習」キュー（間隔反復）

- `study_queue.py`（新規）— `py-fsrs` で次に解く日を決めます。
- `server.py` に `GET /api/study-queue` を追加。
- `static/app.js` / `static/index.html` に出題範囲「今日の学習」と「1日の量」を追加。

**設計上、意図してそうしていること**（レビューではここが妥当かを見てほしい）

1. **FSRSの状態を保存するテーブルを作っていません。** `card_attempts` と `card_marks` から毎回replayして導出します。SQLiteのschemaは変更していません。
   - 理由: 導出値を別に持つと正本と写しがずれる。「リセット」（ここより前を数えないという区切り）が増えるたび再計算が要る。規模が数百件なので毎回計算しても速い。
2. **`enable_fuzzing` を切っています。** 期日を保存せず毎回計算するので、揺らぐと表示が回答のたびに変わるためです。
3. **○×（2択）を4段階へ広げるのに、回答ごとの「自信度」を使っています。** 誤答→Again、正答＋あてずっぽう→Hard、正答＋たぶん→Good、正答＋確信あり→Easy、正答＋記録なし→Good。
4. **間隔の上限を受験日（2026-11-08）までの残り日数にしています。** これがないと「確信あり」で2回正解しただけで次が397日後になり、本番までに二度と出てこないカードができます。
5. **はじめてのカードだけ別枠で絞れます**（`newLimit`）。期日が来た復習は絞っても溜まるだけなので全部出します。

### B. Ankiへの書き出し

- `authoring/tools/anki_export.py`（新規）— タブ区切りテキスト1枚を出します。apkg（SQLite＋zip）にしないのは、Ankiの版が変わると壊れやすいからです。
- 表はA・B1・B2・C、裏が正誤と解説。**表に答えを出さない**のが要件です。

### C. カードを「暗記もの」と「理解もの」に分けた

- カードに `learningType`（`memorize` / `understand`）を追加。8月は1日15分しか取れないので、覚えるしかないものだけを回すためです。
- **既定値を置いていません。** 書いていなければ検証もbundle生成も落とします（分類し忘れが静かに学習範囲へ混ざるのを防ぐため）。
- 別アプリには分けず、共通エンジンの絞り込みとして実装しています。回答履歴と期日は共通のままです。

### D. 装飾記法の検査を強めた

- カード本文は独自の記法（`**太字**` `__下線__` `==強調==` `!!赤!!` `%%人物%%` `@@根拠@@`）を使います。
- `__…==。__` のように「閉じた枠の中に開きっぱなしの記号」があると、既存の2つの検査を素通りして画面へそのまま出ていました。「記法を外しても記号が残らないか」の検査を追加しています。
