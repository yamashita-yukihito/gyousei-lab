# 学習カードの点検・編集・追加をお願いします（ChatGPT向け）

更新日: 2026-07-29
法令基準日: **2026年4月1日**（令和8年度行政書士試験の基準日）
今日の日付や、あなたが知っている最新の法改正日と混同しないでください。

## 0. あなたにお願いしたいこと

添付した JSON（`schemaVersion: "gyousei-card-exchange@1"`）は、行政書士試験の
○×学習カードです。1人の受験者が本番まで使う教材で、すでに回答履歴がたまっています。

次のどれかを、依頼された範囲だけ行ってください。

1. **点検** — ルール違反・法的な誤り・読みにくさを指摘する
2. **編集** — 指摘した箇所を直す
3. **追加** — 不足している論点のカードを新しく作る

## 1. 返してほしい形

**入力と同じ構造の JSON をそのまま返してください。** 説明文だけを返さないでください。

- `editable` の中だけを書き換えます。
- `readonly` は参考情報です。書き換えても取り込み時に捨てられます。
- **変更しなかったカードは、丸ごと削って構いません。** 戻ってきたものだけを見ます。
- 点検だけを頼まれたときは、JSON ではなく指摘の一覧を返してください。

```json
{
  "schemaVersion": "gyousei-card-exchange@1",
  "cards": [
    { "id": "con-eq-framework-001", "editable": { ... 直した中身 ... } }
  ]
}
```

`schemaVersion` は必ず残してください。これが無いと取り込めません。

## 2. カードの構造

画面では、この順で表示されます。**A・B1・B2・C は、回答ボタンより上に出ます。**

| 項目 | JSON | 役割 |
|---|---|---|
| A | `variants.a` | 試験で○×判定する命題。原則として過去問の肢の原文 |
| B1 | `variants.b` | 日常の場面からのやさしい言い換え |
| B2 | `variants.bCasual` | もう一つの角度からの言い換え |
| B2の型 | `variants.bCasualStyle` | 「用語からほどく」「条件を並べる」「時間の流れで追う」など |
| C | `variants.c` | Aを最短にした形 |
| — | ここに回答ボタン | — |
| 正しい形で覚えると | `correction` | Aのどこがどう違うか。**条文番号付きで** |
| 覚え方 | `memoryPoint` | 一行の要点 |
| 解説 | `explanations.normal` | 制度の普通の説明 |
| 深掘り | `explanations.deepDive.background` | なぜその制度がそうなっているのか |
| ひっかけ | `explanations.deepDive.trap` | 本試験での書き換えられ方 |
| 具体例 | `explanations.deepDive.example` | 実際の場面 |
| 常識力 | `explanations.commonSense` | 法律を知らなくても分かる例え |
| ⑤ | `readonly.relatedPastQuestions` | 実際の過去問の肢（原文。編集不可） |
| ⑥ | `crossFieldComparisons` | 混同しやすい制度との1対1比較 |
| ⑦ | `comparisonTable` | 法律ごとに結論が分かれる表 |
| ⑧ | `figures` | 解説図（回答後に出る） |

## 3. 絶対に守るルール

### 3.1 B・C は A と同じ結論の文にする（最重要）

A・B1・B2・C は4つとも**回答ボタンより上**に出ます。だから、

> **A が誤りの命題なら、B・C も同じ誤りの命題を平易にしただけの文にする。**

これを外すと、B・C を読んだ時点で○×が分かってしまい、問題として成立しません。
過去に187枚中44枚がこの違反をしていて、作り直しになりました。

やってはいけない書き方:

| 種類 | 例 | なぜだめか |
|---|---|---|
| 逆の結論 | Aが「復権後も資格なし」／Bが「復権すればまた資格を持てます」 | 答えそのもの |
| 否定でほのめかす | 「〜というわけではありません」「〜する必要はありません」 | 同上 |
| メタ解説 | 「問題文はここがおかしい部分です」 | 同上 |
| 正解の条文を書く | Aが「2年」／Bに「正しくは20年」 | 同上 |
| 引用型の文体 | 「この命題は〜と言っています」「この文は〜としています」 | ×のカードだけがこの型になり、言い回しで答えが割れる |

**断定型で統一してください。** 誤った命題でも断定文で書きます。
正解は、回答後にしか出ない `correction`・`explanations`・`memoryPoint` へ書いてください。

### 3.2 A は肢の原文のまま

A は原則として過去問の肢そのものです。**言い回しを整えないでください。**
装飾記法（後述）を足すのは構いませんが、**記法を取り除いた文字列が元の肢と1文字も違わない**
必要があります。取り込み時に機械照合されます。

### 3.3 文字装飾は「色＝役割」の固定ルール

装飾は飾りではなく、文の役割を色で固定するための記号です。
**同じ記法は全カードで必ず同じ意味**にしてください。

| 記法 | 見た目 | 役割 | 何を囲むか |
|---|---|---|---|
| `%%語%%` | 青いチップ | **だれ** | 人・立場・当事者。保証人、行政庁、審査請求人 |
| `__語__` | 緑の下線 | **条件・期間** | 要件、場合分け、数字、期限。1か月以上、善意無過失 |
| `**語**` | 濃い緑の太字 | **用語・制度** | その論点の中心にある法律用語。詐術、即時取得、教示 |
| `==語==` | 黄色のマーカー | **結論** | できる／できない、有効／無効、認められる |
| `!!語!!` | 赤字 | **判定の分かれ目** | 本試験で書き換えられる箇所、数字、例外 |
| `@@語@@` | 灰色の小さめ | **根拠・補足** | 条文番号、判例番号。民法145条、最判平11.10.21 |

決まりごと:

- **A には赤（`!!`）を使わない。** A は肢の見え方をそのまま出す場所です。
- **赤は「誤っている箇所」ではなく「判定の分かれ目」を指す。** この意味なら○のカードにも
  付けられるので、赤の有無で答えが割れません。
  - 良い例（×のカード）: 「!!復権の前か後かで結論が動くのか!!が、判定の分かれ目です」
  - 悪い例: 「!!『復権をした後においても』が誤りです!!」→ これは `correction` に書く
- **黄（`==`）は1文につき原則1か所。** 対になった2つの結論を1文で示すときだけ2か所まで。
- 読点で区切られたひとまとまりにつき装飾は1〜2か所まで。1文で多くても4か所。
- 記法の入れ子は不可。同じ記法を隣り合わせにしない（`!!A!!!!B!!` ではなく `!!AB!!`）。
- **⑦の本文には装飾記法を使わない。** 表の中は素の文字列です。
- 迷ったら装飾しない。無装飾の地の文があるほうが、装飾した箇所が効きます。

### 3.4 出題された論点だけをカードにする

このサービスは**頻出論点を○×にする教材**であり、法改正の解説サイトではありません。

- 過去20年に一度も問われていない条文を、法改正があったという理由だけでカードにしない。
- **号番号・項番号のずれをひっかけにしない。** 本試験が問うのは条文の結論です。
- 法改正は独立カードにせず、既存カードの中身を現行法へそろえる形で反映する。

`readonly.frequency` に、その論点が20年で何問出たかが入っています。参考にしてください。

### 3.5 B の書き方

- 頭が回っていないときでも、一度で場面を想像できる言葉を使う。
- 専門用語を専門用語のまま言い直さない。最初に出る専門用語はその場でほどく。
- B1 は日常の場面から、B2 は「用語からほどく」「条件を並べる」「時間の流れで追う」など、
  問題に合う方法を選ぶ。選んだ型を `bCasualStyle` に書く。
- 1段落を長くしすぎない。改行は意味の切れ目だけに使う。
- 短さだけを目的にしない。最短の確認は C の役割です。

### 3.6 C の書き方

- **A の命題を最短にした形**にする。「正しい結論の要約」ではありません。
- **その結論が成り立つ場面を必ず残す。** 短くするために場面を落とすと、別の制度と区別が
  つかなくなります。
  - 悪い例: `形式不備 → 補正を求めるほかなく、拒否できない`
  - 良い例: `申請 → 形式上の要件に不備 → 補正を求めるほかなく、拒否できない`
- 矢印でつないで「場面 → 条件 → 結論」の順に並べると、短いまま場面を残せます。

### 3.7 correction の書き方

- A のどこがどう違うのかを**条文番号付きで**書く。ひとことの言い換えで終わらせない。
- A が複数のことを言っている肢なら、**その全部**に答える。
- 条文番号・判例は 2026年4月1日時点の現行法で確認したものだけを書く。
  **自信がないときは条文番号を書かず、その旨をコメントで伝えてください。**
  誤った条文番号は、間違いを覚えさせるので最も害があります。
- **法令基準日は 2026年4月1日で、今日の現行法とは違います。** e-Gov を基準日の指定なしで
  開くと、基準日より後に施行された改正後の条文が表示されます。時点を指定するには
  `https://laws.e-gov.go.jp/law/<法令ID>?occasion_date=20260401` の形式を使ってください。
  ページ上部に「時点 令和8年（2026年）4月1日」と出ているかを必ず確認します。
- **項番号は改正でずれます。** 実例として、行政手続法15条は 2026年5月21日施行の改正で
  3項が3項と4項に分かれ、31条が準用する条文も「15条3項」から「15条3項・4項」へ変わりました。
  基準日では **15条3項** が正しい値です。**改正で動く項番号は、そもそも書かないほうが安全です**
  （試験で問われるのは「16条が準用されるので代理人は使える」「18条は準用されないので
  資料閲覧はできない」という結論のほうです）。
- **元のカードに書かれている条文番号を「正しい」と見なさないでください。** 誤りが残っている
  場合があります。上の実例も、元のカードに入っていた誤りでした。

### 3.8 ⑥と⑦

- ⑥ `crossFieldComparisons` は、試験で**本当に混同しやすい**1対1の比較だけに付ける。
  「同じ行政法だから」など広すぎる関連付けはしない。無いカードは空配列にする。
- ⑥は**本文に書けない他分野との混同**を置く欄である。すでに `correction` や
  `deepDive.trap` に書いた内容を⑥へ書き写さない。重複は情報量を増やさない。
- **すでに⑥が入っているカードで、それを別の比較へ置き換えない。** 内容を足したいときは
  配列へ追加する。`relatedCardId` はカード間のリンクなので、消したり書き換えたりしない。
- ⑦ `comparisonTable` は、**同じ場面なのに根拠になる法律が変わると結論が変わる**論点だけ。
  `rows` は2〜4行、`label`（法律名）は重複不可。`memoryCue` には並びだけでなく
  **なぜそう分かれるのか**を書く。装飾記法は使わない。
- **すでに入っている⑦から行を減らさない。** 文言を良くするのは歓迎だが、
  比較対象の法律を落とすと横断ひっかけの対策が弱くなる。

### 3.9 ⑧ 解説図（`figures`）

図はカードに載せられます。**回答後の解説の中**に出ます（A・B1・B2・Cの並ぶ出題面には出ません）。

```json
"figures": [
  {
    "src": "assets/card-figures/admin-law-invalid-act-nullity.png",
    "alt": "画像が出ないときや読み上げで使う説明。何を比べた図かを1文で",
    "caption": "図の下に出る短い見出し",
    "placement": "correction"
  }
]
```

- `placement` は、その図をどの説明の直後に出すかです。省略すると `correction` になります。

  | 値 | 出る場所 | 向いている図 |
  |---|---|---|
  | `correction` | 「正しい形で覚えると」の直後 | 正誤の分かれ目そのものを示す図 |
  | `normal` | ①普通の解説の直後 | 制度の全体像・判定順を示す図 |
  | `deepDiveBackground` | ②深掘りの「制度の背景・理由」の直後 | なぜそうなっているかの条件関係を示す図 |
  | `deepDiveTrap` | ②深掘りの「試験のひっかけ」の直後 | 混同しやすいものを並べた比較表 |
  | `deepDiveExample` | ②深掘りの「具体的な場面」の直後 | 場面を追った図 |

- **1枚のカードに2枚まで。** 図を増やすより、1枚に収まる整理にしてください。
- **同じ図を複数のカードへ置かないでください。** いちばん効くカード1枚に置き、
  関連するカードからは⑥の `relatedCardId` で結びます。
- `src` は `assets/card-figures/` の下だけです。外部URLや他のフォルダは受け付けません。
- **画像ファイルそのものはMac側で置きます。** ChatGPTから `figures` を書くのは、
  すでに置いてある画像を参照するときだけです。新しい図は画像ファイルとして別に渡してください。
- `alt` と `caption` は必須です。装飾記法（`**` `__` など）は使えません。
- 図は本文の置き換えではありません。図を足したからといって `correction` や深掘りを削らないでください。

**図の中身は、本文より慎重に確認してください。** 図は一目で覚えてしまうので、
間違った図は間違った本文より害が大きいです。図に条文番号を入れるときは、
3.7の法令基準日の注意がそのまま当てはまります。

### 3.10 `evidenceHighlights` は⑤の肢原文に出てくる語だけ

この配列は、⑤「実際に出た肢」の**原文に対してそのまま文字列一致で色を付ける**ための語です。
カードの要点キーワード集ではありません。原文に無い語を入れても、画面では何も起きません。

- 入れる前に、添付JSONの `readonly.relatedPastQuestions` の本文に
  **その文字列がそのまま含まれているか**を確認してください。
- 条文用語・法令の言い回しをそのまま入れるのが基本です。
  よい例: `補正` / `形式上の要件` / `許認可等` / `相当の期間` / `地方公共団体の機関` / `条例`
- 悪い例: `2026年4月1日基準` / `31条の選択的準用` / `申請の握り込み` / `聴聞との保障差` /
  `行政庁の調査懈怠`。過去問の肢にこういう表現は出てきません。
- **すでに入っている値を全部入れ替えないでください。** 足すなら追記してください。

## 4. ○と×のバランス

**科目ごとに○が3〜5割**に収まるようにしてください。
誤りの肢は解説の題材として書きやすいので、放っておくと自然に×へ寄ります。
過去に憲法20枚がすべて×になり、「×と答え続ければ全問正解」という状態を作ってしまいました。

○のカードを作るときは、その設問の**正解肢の原文**を A に使ってください。
判例や条文の言い回しをそのまま覚える練習になります。

## 5. 新しいカードを追加するとき

`cards` の末尾へ、次を含む形で足してください。

```json
{
  "id": "con-gen-new-topic-001",
  "editable": {
    "topic": "総論", "subtopic": "覚える論点をひとつ",
    "correct": true,
    "variants": { "a": "...", "b": "...", "bCasual": "...", "bCasualStyle": "条件を並べる", "c": "..." },
    "correction": "...", "memoryPoint": "...",
    "explanations": { "normal": "...", "deepDive": { "background": "...", "trap": "...", "example": "..." }, "commonSense": "..." },
    "legalBasis": [ { "label": "憲法96条（2026年4月1日基準）", "url": "https://laws.e-gov.go.jp/law/321CONSTITUTION" } ],
    "evidenceHighlights": ["目立たせたい語", "..."],
    "crossFieldComparisons": []
  },
  "readonly": {
    "subjectId": "constitutional-law", "category": "憲法", "clusterId": "constitution-general",
    "sourceRefs": [ { "rawId": "<添付JSONにある原問ID>", "choiceNumber": "2", "relationship": "provider-explanation-primary" } ],
    "relatedPastQuestions": [ { "choiceId": "<添付JSONにある肢ID>", "relation": "same_rule" } ]
  }
}
```

- `id` は既存と重複しない安定した英数字にしてください。**あとから変えると回答履歴と切れます。**
- `subjectId` は `administrative-law` / `civil-law` / `commercial-law` /
  `constitutional-law` / `general-knowledge` / `legal-foundations` のどれか。
- **`relatedPastQuestions` は1本以上必要**です。`choiceId` は、添付JSONの中に実在するものだけを
  使ってください。存在しない `choiceId` を書くと取り込みが止まります。
  **知らない肢を作らないでください。**
- `relation` は `same_rule` / `wording_variant` / `opposite_claim` / `exception` /
  `contrast` / `same_topic` のどれか。
- 頻出度は取り込み側で数え直すので、書かなくて構いません。

## 6. やってはいけないこと

- **既存の `id` を変えない。** 回答履歴との対応が切れます。
- **`readonly` の中身を変えない。** 特に `frequency` は20年分の原問と突き合わせた監査値です。
- **⑤の肢の本文を書き換えない。** 実際の過去問の原文をそのまま表示する欄です。
- **知らない条文番号・判例番号を書かない。** 分からないときは書かずに伝えてください。
- **出典のない論点でカードを作らない。** 添付JSONに肢が無い論点は追加できません。
- 装飾記法を本文の意味を変える形で足さない。記法を外すと元の文に戻る必要があります。

## 7. 回答履歴とカードIDの関係

**回答履歴はカードIDだけで引き継ぎます。** A・B・C・正解・法令基準日のどれを直しても、
同じカードIDなら過去の回答・卒業回数・「絶対覚えた」がそのまま残ります
（2026-07-30に変更しました。それ以前は A・C・correct を変えると履歴が判定から外れました）。

- 内容が誤っているなら、履歴を気にせず直してください。
- ただし、**論点そのものが別物になる書き換えはしないでください。** 例えば
  「弁明では代理人を選任できる」を「聴聞では文書等の閲覧を請求できる」に変えると、
  同じカードIDのまま中身が入れ替わり、過去の履歴がその論点の履歴として残ってしまいます。
  別の論点にしたいときは、既存カードを直すのではなく**新しいカードとして追加**してください。
- 表現を整えるだけの A・C の書き換えは、遠慮なく提案してください。

## 8. 返すときに一緒に書いてほしいこと

JSON とは別に、次を短くまとめてください。

1. 何枚を、どう直したか
2. A・C・correct を変えたカードのID（履歴に影響するため）
3. 法的に自信が持てなかった箇所と、その理由
4. 直さなかったが気になった箇所
