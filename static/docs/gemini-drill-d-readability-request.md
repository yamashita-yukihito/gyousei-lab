# Geminiへの依頼：演習D案の「文章の読みやすさ」だけを点検する

- 更新日: 2026-10-28
- 依頼元: Mac側の Claude（行政書士試験の学習ラボ `gyousei-lab`）
- 状態: 依頼中
- 一緒に渡すファイル: `drill-d/` の下にある7つのMarkdownのうち1つ（`minpo-1.md`〜`minpo-3.md`、`gyosei-1.md`・`gyosei-2.md`、`kenpo.md`、`small.md`）

## 1. お願いしたいこと

行政書士試験（2026年11月8日）に向けた自習用の○×ドリルです。添付したMarkdownの文章を、**読みやすさだけ**の観点で点検し、
直したほうがよい箇所を下の「5. 返し方」の形で返してください。

**見てほしいのは読みやすさだけです。** 次のことは見なくて構いません（別の担当がすでに確かめています）。

- 試験に出る論点かどうか、頻出かどうか、論点の過不足
- 法律・判例の内容が正しいかどうか、○×の結論が正しいかどうか
- ひっかけとして良い問題かどうか

## 2. 読み手

- 受験者本人が1人で使います。法律の専門家ではありません。
- **疲れて頭が回っていない時でも、一度読めば場面が浮かぶこと**が目標です。
- 最初の2周は、答えと解説を最初から開いたまま上から読みます。3周目からは答えを隠して解きます。

## 3. ドリルの仕組み（点検の前提）

- 1つの章は8問です。章の初めに「章の共通事例」があり、各問はそこから**事実を1つだけ変えて**進みます。`delta` が「前 → 今回」の変化です。
- 人物は**役割で固定**しています（例：民法では、のび太＝守られる側、ジャイアン＝強引な側、スネ夫＝あとから出てくる第三者）。各章の「配役（固定）」に対応が書いてあります。**名前を別の人物に替えたり、役割を変えたりしないでください。**
- `statement`（○×を判断する文）は、**わざと誤りの文になっている問題があります**（見出しに「正解×」とある問題）。これは誤りではありません。**×の文を正しい文へ直さないでください。** 読みにくい言い回しの手直しだけをお願いします。
- `currentScenario`（今回の事実）と `statement` は、答えを見る前に表示されます。**ここに答えが分かる語を足さないでください**（例：「〜なので無効」のような結論、「善意なので保護される」のような評価）。
- `explanation.*` は答えのあとに表示される解説です。項目の役割は次のとおりです。
  - `summary` 答えの説明（○か×で始まる）
  - `fact` ○×を分けた事実（短い句）
  - `rule` 条文・判例の番号（短い句）
  - `conclusion` この事例の結論（短い句）
  - `protectWho` と `why` 誰を守るルールか、その理由
  - `ifOpposite` 反対の結論だと何が困るか
  - `legalSense` 本試験でのひっかけ方や、専門家の感覚へ合わせる補足
  - `minimum` 最小限の覚え方（1行で覚えられる長さ）
  - `next` 次の問へのつなぎ

## 4. 見てほしい点

優先順に並べています。

1. **一度で場面が浮かぶか。** 誰が・誰に・何をしたかが、読み返さずに分かるか。主語が抜けていないか。代名詞や「これ」「その」が何を指すか迷わないか。
2. **一文が長すぎないか。** 読点だらけの長い一文は、意味の切れ目で2文に分けてください。
3. **専門用語が、説明なしのまま続いていないか。** 試験に出る用語（「善意」「対抗」「処分」など）は**消さずに残し**、必要なら短い言い換えを添えてください（例：「善意（事情を知らない）」）。
4. **解説が○×を分ける語をはっきり示しているか。** 遠回しで要点がぼやけている箇所。
5. `minimum` が長すぎて1行で覚えにくくないか。
6. 前後の問のつながり（`delta` と `next`）が不自然でないか。
7. 誤字・脱字・表記ゆれ（「取消し／取り消し」は法令の表記に合わせて「取消し」でよい）。

## 5. 守ってほしいこと

- **意味・結論・○×を変えないでください。** 法律の条件（「〜に限り」「〜を除き」「当然に」など）を削ったり、足したりしないでください。
- 条文番号・判例の日付・年数・期間などの**数字は変えない**でください。
- 人物の名前と役割を変えないでください。
- 改行は入れないでください（画面が改行を自動で入れます）。装飾記号（太字の `**` など）も使わないでください。
- 全部を書き直す必要はありません。**直す効果がはっきりしている箇所だけ**を選んでください。目安は、1ファイルにつき多くても40件です。効果の大きいものから順に並べてください。
- 文体は「です・ます」（事例文・解説）と「である」調の短い句（`fact`・`rule`・`conclusion`・`minimum`）が混ざっています。項目ごとの今の文体に合わせてください。

## 6. 返し方

Markdownで、次の形をそのまま繰り返してください。Mac側で機械的に当てはめるので、**「今」の文は添付ファイルから1文字も変えずに写してください**（項目の文全体でも、その一部でも構いません。一部のときは、その範囲が項目の中で1回しか出てこない長さにしてください）。

```markdown
### gyosei-d-sg-001
- 項目: currentScenario
- 今: 市は、のび太の子が通っている特定の市立保育所だけを廃止する条例を制定しました。
- 案: 市は、のび太の子が通う特定の市立保育所だけを廃止する条例をつくりました。
- 理由: 「制定しました」より場面が浮かびやすい（例）
```

- 1つの問に複数の指摘があるときは、同じ問IDの見出しの下に `- 項目:` からの4行を続けて書いてください。
- 章の文（`lead`・`goal`・`baseScenario`・`remedyGuide`・`summaryTable.note`）への指摘は、問IDの代わりに `### 章 suit-gate` のように章IDを書いてください。
- 最後に `## 全体の印象` として、ファイル全体で目についた癖（例：「〜という」が多い、主語の省略が多い）を3〜5行で書いてください。

返答はファイル名 `GEMINI_DRILL_D_READABILITY_RESPONSE_<添付ファイル名>.md`（例：`GEMINI_DRILL_D_READABILITY_RESPONSE_gyosei-2.md`）として保存できる形にしてください。
